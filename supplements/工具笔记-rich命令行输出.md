# 工程工具笔记：rich命令行输出

命令行里同时打印订单、模型响应和进度，长字典很快会淹没关键状态。Rich可以把同一批信息展示成表格、进度和结构化对象，让人更容易找到“哪项在等待，哪项失败”。它负责展示，不负责使业务正确。

## 先决定需要看什么

售后任务最小展示可以只有任务编号、当前阶段、等待内容和业务结果。完整模型输入、密钥、用户原文不应因为方便调试就全部输出。

| 信息 | 适合的展示 |
| --- | --- |
| 多项任务状态 | `Table` |
| 总量明确的工作 | `Progress` |
| 总量未知的等待 | 阶段文字或不定进度 |
| 嵌套返回对象 | 格式化打印 |
| 随时间更新的状态 | `Live` |

先维护清楚的任务数据，再把它交给展示层。不要只把状态藏在颜色里，否则重定向或无色终端中就失去含义。

## 安装并运行独立示例

在自己的Python环境中安装可选展示依赖：

```powershell
python -m pip install rich
python -X utf8 examples/23-32-assistant/rich_demo.py
```

完整脚本见[rich_demo.py](../examples/23-32-assistant/rich_demo.py)。它展示教学状态表、原样外部文字和三个已知步骤的进度，不执行订单操作或模型调用。

`Console`作为统一输出入口，`Table`管理行列，`Text`承载不需要解释成标记的文字。使用同一个Console可以减少不同输出入口相互穿插。

## 外部文字不要自动解释成样式

Rich默认支持`[red]`等样式标记。用户原话或工具输出也可能包含方括号，如果直接作为标记处理，可能改变展示或导致解析错误。

<!-- example-kind: usage -->
```python
from rich.console import Console

console = Console()
console.print("用户原文：[red]请按原样显示[/red]", markup=False, highlight=False)
```

关闭标记不会屏蔽敏感信息，也不是安全过滤。它只是避免外部字符串被当作展示指令。表格单元也可使用`Text`明确按文本处理。

## 进度应该来自实际完成量

若有三项核对，完成一项才推进一次；如果不知道后面还会新增多少工作，就不要展示凭空计算的百分比。图中走过的节点数也不能直接代表任务完成比例。

配套进度只遍历三个固定教学步骤，真实应用需要把确认后的完成事件接到`advance`或`update`。开始查询时不能把该项标为已完成。

`Progress`内部也有Console，执行期间的文字可以通过`progress.console.print()`输出。多线程输出最好集中到消费端，工作线程只产生事件，避免表格和原始`print`乱序。

## 日志与动态面板用途不同

`Live`适合看当前状态，刷新后旧画面可能被替换；持久日志适合事后回溯，必须保留任务、时刻、阶段与结果。漂亮的面板不能代替日志。

需要标准日志时，可配置`RichHandler`作为显示处理器，另保留适当的文件日志。异常堆栈可能含参数和路径，展示与保存范围应按实际用途选择。

终端输出被重定向到文件或CI时，颜色和刷新行为可能变化。机器需要消费的结果应提供稳定JSON或JSONL入口，不依赖从彩色表格重新解析业务数据。

## 展示正确还要与业务核对

看见“等待确认”，应能找到具体草稿；看见“已提交”，应有申请编号；失败应带可定位的任务与类别。Rich让这些信息更易读，依据仍来自状态与业务结果。

这份工具笔记可以随流式进度和综合应用阅读，不需要为了终端美化改变核心业务实现。
