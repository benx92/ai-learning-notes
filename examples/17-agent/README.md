# 第17章：观察模型与工具执行循环

正文先解释Agent、执行循环与状态，再逐轮推演查询和申请准备。ReAct部分用同一案例解释推理、行动与观察怎样交替；本脚本只用固定响应检查消息与执行，不实现真实模型的ReAct推理。本目录用 `trace_loop.py` 观察已有循环：它导入第15章 `tool_demo.py` 的 `run()`，不另写一套执行器，也不使用框架。

使用Python 3.10或更新版本，只依赖标准库与仓库内的 `examples/15-tool-calling/tool_demo.py`。请保留两目录的相对位置。固定离线规则替代模型输出，实际执行虚构订单查询；不请求模型API，不需要Key，不产生API费用。这里的“模型调用次数”统计替代函数被调用的次数，不是付费请求记录。

在本目录运行：

```powershell
python trace_loop.py
python trace_loop.py "查一下退款状态"
python trace_loop.py "查一下订单A2002的退款状态"
python trace_loop.py --json
```

| 输入 | 替代模型调用次数 | 工具执行次数 | 观察重点 |
| --- | ---: | ---: | --- |
| A1001（默认） | 2 | 1 | 第二次输入新增原调用请求和工具结果 |
| 没有订单号 | 1 | 0 | 询问后结束本次运行，不会自动等待或恢复 |
| A2002 | 2 | 1 | 不可访问结果被回填，结束不等于业务查询成功 |

`--json`输出每次调用前的完整消息快照与对应输出，以及最终消息历史。快照独立保存，后续追加消息不会改写前一轮记录。`verification-offline.json`是本地运行生成的A1001记录和三场景摘要，不是在线模型评测。

A3003的资格查询、等待原因、恢复任务和草稿准备，在正文中用于设计多步循环；本脚本未实现这套在线Agent。已经实现的草稿业务服务在 `../15-tool-calling/return_demo.py`，不要把独立业务测试视为模型自主完成的实测。
